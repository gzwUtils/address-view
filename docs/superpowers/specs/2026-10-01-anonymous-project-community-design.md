# 匿名账户与项目论坛设计

日期：2026-10-01
范围：`address-plat` 前端、`address-view` 后端及生产环境 `/api` 反向代理

## 目标与阶段

门户保留现有项目发现和发布能力，新增类似传统论坛的板块、主题帖和按时间排列的楼层回复。访客不用注册或登录：浏览器首次打开门户时，服务端自动创建随机账户和随机昵称。用户可围绕任意项目发起讨论，也可发布不关联项目的交流帖。

本轮交付匿名账户、项目归属改造、论坛帖子与回复、基础治理和入口整合。帖子里的连续回复承担“聊天交流”体验，页面打开时每 10 秒检查新回复，并提供手动刷新。独立的一对一私聊、群聊、在线状态、WebSocket、图片上传和通知中心作为后续独立阶段；本轮不在界面上把楼层回复标成“即时聊天”。

验收重点：首次访问自动获得账户；刷新后保留身份；换浏览器后凭账户 ID 和恢复码找回同一账户，能继续查看和回复原来的讨论；可改昵称、发项目、发帖、回复和管理自己的内容；无法仅通过修改请求里的用户 ID 管理他人内容；公开读帖无需账户；手机端可完整参与讨论。

## 方案选择

1. **永久账户 ID + 恢复码 + 浏览器会话（采用）**：服务端生成不可变的公开账户 ID、随机昵称和只展示给本人的高强度恢复码。日常浏览由 HttpOnly Cookie 保持会话；换浏览器时输入账户 ID 和恢复码，服务端签发新会话，继续使用同一账户。用户不需要注册真实姓名、手机号或企业账号。生产环境需要 HTTPS，以及前端和 `/api` 的同源部署。
2. 仅靠账户 ID 找回：输入最少，但 ID 会出现在作者资料中，知道 ID 的人就能冒用作者，不能用于恢复。
3. 邮箱/手机号或企业统一登录：可以在恢复码遗失后验证身份，但要收集额外信息；用户当前希望随机账户，本轮不采用。

账户 ID 永久不变，帖子、回复和项目都关联这个 ID，不随 Cookie 失效而消失。恢复码是账户的长期密钥，必须保密并由用户保存；服务端只保存摘要，不会通过查询接口再次显示原码。浏览器 Cookie 丢失或更换设备后，输入 ID 和恢复码即可回到原账户，多个浏览器可以同时使用。若所有已登录浏览器都遗失且没有保存恢复码，也没有绑定邮箱/手机等其他凭证，服务端无法仅凭公开 ID 判断谁是主人；可在仍登录的浏览器中重新生成恢复码。这个限制在首次领取账户时明确提示。

## 页面和体验

全局导航增加「社区」，首页在项目入口之后展示最新讨论，项目卡片及详情页提供「讨论这个项目」。社区首页展示固定的「项目分享」「技术交流」「闲聊」三个板块，每个板块显示主题数和最近活跃时间；板块页按最近回复排序，支持按最新发布排序和关键词搜索。主题卡片展示标题、作者昵称、发布时间、回复数、关联项目和最后回复时间。项目详情显示关联主题及「发起讨论」入口；发帖时自动带入项目关联，但用户可取消。资源广场的类型筛选增加「帖子」，关键词查询可检索帖子标题与正文。

主题页展示首帖、楼层编号、作者昵称、发布时间及平铺回复。回复可引用某一楼层，但仍按时间顺序排列，避免深层嵌套。新回复出现时显示数量提示；用户点击提示后加载并定位，避免阅读中突然跳动。发帖或回复成功后立即显示结果；失败时保留草稿并给出明确原因。用户可编辑或删除自己的主题与回复；删除采用软删除，保留楼层位置与后续回复的上下文。昵称修改后，历史帖子显示当前昵称。

浏览器首次打开门户时领取账户，不弹注册页面；导航显示随机昵称，点击进入「我的账户」面板，可看到并复制固定账户 ID、修改昵称、重新生成恢复码，以及进入「我的讨论」查看自己发起和参与的主题。首次创建时显示一次恢复码，提供复制和下载纯文本身份卡的操作；关闭后不再显示原码，但在当前已登录浏览器中可重新生成，新码生效时旧码立即失效。登录其他浏览器时，点击「使用已有账户」，输入 ID 和恢复码；若该浏览器临时新账户已有内容，切换前提示这些内容不会自动合并。默认昵称从预设词库加随机数字生成，碰撞时重试，长度 2–20 个字符；修改时去除首尾空格，限制长度和不可见控制字符。前端隐藏非作者的编辑按钮只是体验处理，最终权限判断在服务端。

## 身份、部署和既有数据

`POST /api/guest-sessions` 创建账户时生成不可预测的会话密钥（至少 256 位）和独立恢复码（至少 160 位），只在这次响应返回原始恢复码；数据库仅保存两者的摘要、账户关系和会话失效时间。账户另有稳定、唯一、便于复制的公开 ID，例如 `P-7K4M9Q2X`，它不能单独用于鉴权。`POST /api/guest-sessions/restore` 校验公开 ID 与恢复码后，为已有账户签发新的会话 Cookie；恢复接口按账户 ID 与 IP 双重限流，失败时不透露 ID 是否存在，也不自动注销其他浏览器。`POST /api/me/recovery-code/rotate` 仅允许现有会话调用，生成并一次性返回新码，同时废止旧码。`GET /api/me` 返回当前 ID/昵称，`PATCH /api/me` 修改昵称，`GET /api/me/discussions` 返回本人发起或回复过的主题并按最近活动分页。

会话 Cookie 设置 `HttpOnly; Secure; SameSite=Lax; Path=/api`。生产环境使用 HTTPS，并让门户与 `/api` 处于同一站点；本机 HTTP 开发仅在 localhost/127.0.0.1 关闭 `Secure`，由 Vite 的 `/api` 代理连接后端。前端 API 默认改用相对路径 `/api`。应用启动时先请求 `GET /api/me`；没有会话且本浏览器从未领取过账户时自动创建，曾有账户却丢失会话时先显示恢复入口。前端可在本地保存公开账户 ID 和“曾有账户”标记用于提示，但它们不提供写权限；公开 GET 本身仍允许无会话访问。会话有效期 365 天，活跃时续期；失效后可以恢复原账户。前端先经 `GET /api/csrf` 获取 CSRF 令牌，再在所有变更请求携带 `X-CSRF-TOKEN`；服务端同时校验 Origin。账户不会基于浏览器指纹生成，也不接受请求体、`X-User-Id` 或前端本地存储的 ID 作为权限凭据。

新建项目的 `owner_account_id` 由服务端从会话填写；更新和删除均检查数据库中的该字段。前端提交的旧 `ownerId`/`ownerName` 不再决定归属，显示昵称来自账户表。已有项目保留公开展示，旧 `owner_id`/`owner_name` 字段保留以便迁移；由于旧 ID 可伪造，不能自动认领或据此授权编辑。需要恢复某个旧项目的编辑权时，由管理员核对后执行一次性归属映射。既有未提交的前端改动不混入此次改造。

现有「落地舱」使用浏览器生成的 `userId`，不作为社区账户的身份依据。本轮账户只覆盖项目与社区的作者操作；落地舱身份迁移单独设计，避免把不可信的旧 ID 直接绑定新账户。页面对用户展示的“账户”指项目与社区账户，落地舱暂沿用现有个人数据入口。

## 数据和接口

新增 `community_account`（内部 ID、唯一公开 ID、昵称、恢复码摘要、状态、时间）、`community_session`（账户 ID、会话密钥摘要、失效与撤销时间）、`community_board`（编码、名称、描述、排序、状态）、`community_topic`（板块 ID、作者账户 ID、可空项目 ID、标题、正文、回复数、最后回复时间、状态、时间）、`community_reply`（主题 ID、作者账户 ID、可空引用回复 ID、正文、楼层号、状态、时间）、`community_report`（举报者、目标类型与 ID、原因、状态、时间）；项目表新增可空的 `owner_account_id`。对账户公开 ID 和恢复码摘要、主题列表的板块/最后回复时间、回复的主题/楼层号、项目关联和会话摘要建立索引。所有列表使用后端分页与总数，禁止一次拉取整个论坛。

公开读取：`GET /api/community/boards`、`GET /api/community/topics?board=&projectId=&keyword=&sort=&page=&size=`、`GET /api/community/topics/{id}`、`GET /api/community/topics/{id}/replies?page=&size=`；项目页用 `projectId` 查询关联主题。写入：`POST /api/community/topics`、`PATCH /api/community/topics/{id}`、`DELETE /api/community/topics/{id}`、`POST /api/community/topics/{id}/replies`、`PATCH /api/community/replies/{id}`、`DELETE /api/community/replies/{id}`、`POST /api/community/reports`。管理员使用 `POST /api/admin/session` 建立单独会话，经 `GET /api/admin/community/reports` 查看待处理举报，再由 `PATCH /api/admin/community/reports/{id}` 处理并可隐藏对应内容。响应统一沿用现有 `ApiResponse` 结构；错误区分 400 校验失败、401 会话缺失/过期、403 非作者、404 内容不存在、409 已删除/状态冲突、429 频率限制。板块编码固定，发帖可选已存在且可见的项目；关联项目不要求发帖者是项目所有者。

主题标题 5–120 字，主题正文 10–10000 字，回复正文 1–2000 字。正文首版为纯文本，换行可保留，URL 作为安全链接识别；前后端都不渲染用户提交的 HTML。列表返回摘要和计数，详情返回正文；作者昵称通过账户表查询，因此改名会更新历史展示。楼层号在事务中分配，不因软删除重排；新增和删除回复时在同一事务中维护回复数和最后活跃时间。

## 治理、异常与验证

公开匿名写入需对账户和 IP 做频率限制，初始阈值为每小时每账户 5 个主题、30 条回复，每日 5 次改名、10 次举报，每小时每 IP 最多领取 20 个账户；阈值从服务端配置调整。重复或超长内容给出可理解的错误。每条主题和回复提供举报入口，举报者须有有效会话。作者可软删除自己的内容，管理员可隐藏内容并处理举报。管理员通过服务端配置的独立密码建立管理会话，使用受保护的管理接口处理举报；普通随机账户不能自行提升为管理员。现有内容和 AI 管理接口若继续对公网开放，也必须在上线社区前加上同一服务端管理权限，不能沿用前端显示的“运维”角色当作授权。

接口失败时保留页面已加载内容与输入草稿，显示重试；若账户 Cookie 过期，前端先提示“使用账户 ID 和恢复码找回原账户”，并可明确选择创建新账户，避免静默把原草稿发成另一位作者的内容。恢复失败时保留输入但不回显完整恢复码到日志或 URL。板块或主题被隐藏后对普通用户返回 404。数据库迁移先增加新表和项目归属字段，再部署 API 与前端；在两端切换期间将旧项目写接口暂时关闭或一起发布，防止旧客户端绕过新归属检查。

验证包括：首次领取与刷新复用账户；在浏览器 A 发帖、浏览器 B 用 ID 和恢复码恢复后继续回帖并查看「我的讨论」；错误或被猜测的 ID/恢复码不能恢复；恢复码轮换使旧码失效且不影响现有会话；Cookie 丢失后可恢复；昵称修改后旧帖显示新昵称；项目关联和跨板块检索；分页与并发回复楼层不重复；作者和非作者的编辑/删除；伪造旧 `X-User-Id` 无效；跨站请求、限流、举报和软删除；桌面与手机端的读帖、发帖、引用及新回复提示。后端通过单元和集成测试覆盖身份/归属/事务，前端通过构建、静态检查与浏览器关键路径验证。
