# 匿名账户与项目论坛设计

日期：2026-10-01
范围：`address-plat` 前端、`address-view` 后端及生产环境 `/api` 反向代理

## 目标与阶段

门户保留现有项目发现和发布能力，新增类似传统论坛的板块、主题帖和按时间排列的楼层回复。访客不用注册或登录：浏览器首次打开门户时，服务端自动创建随机账户和随机昵称。用户可围绕任意项目发起讨论，也可发布不关联项目的交流帖。

本轮交付匿名账户、项目归属改造、论坛帖子与回复、基础治理和入口整合。帖子里的连续回复承担“聊天交流”体验，页面打开时每 10 秒检查新回复，并提供手动刷新。独立的一对一私聊、群聊、在线状态、WebSocket、图片上传和通知中心作为后续独立阶段；本轮不在界面上把楼层回复标成“即时聊天”。

验收重点：两个浏览器自动获得不同账户；同一浏览器刷新后保留身份；可改昵称、发项目、发帖、回复和管理自己的内容；无法仅通过修改请求里的用户 ID 管理他人内容；公开读帖无需账户；手机端可完整参与讨论。

## 方案选择

1. **服务端随机账户 + HttpOnly Cookie（采用）**：服务端生成身份和会话密钥，并验证每次写操作。用户没有注册步骤，浏览器自动携带凭据。生产环境需要 HTTPS，以及前端和 `/api` 的同源部署。
2. 浏览器自行生成用户 ID 并传给后端：最容易沿用现有代码，但任何人都可以伪造他人的 ID；不用于论坛作者和项目归属。
3. 企业统一登录：适合需要组织身份和跨设备恢复的场景，但用户明确不需要，且会增加参与门槛。

账户只识别当前浏览器，不代表真实身份。用户删除站点 Cookie、使用另一浏览器或长期离线超过会话期限后会获得新账户；旧帖子和项目仍公开，但不能自行恢复编辑权。首版不做恢复码或跨设备同步，界面在改昵称处清楚提示这一点。

## 页面和体验

全局导航增加「社区」，首页在项目入口之后展示最新讨论，项目卡片及详情页提供「讨论这个项目」。社区首页展示固定的「项目分享」「技术交流」「闲聊」三个板块，每个板块显示主题数和最近活跃时间；板块页按最近回复排序，支持按最新发布排序和关键词搜索。主题卡片展示标题、作者昵称、发布时间、回复数、关联项目和最后回复时间。项目详情显示关联主题及「发起讨论」入口；发帖时自动带入项目关联，但用户可取消。资源广场的类型筛选增加「帖子」，关键词查询可检索帖子标题与正文。

主题页展示首帖、楼层编号、作者昵称、发布时间及平铺回复。回复可引用某一楼层，但仍按时间顺序排列，避免深层嵌套。新回复出现时显示数量提示；用户点击提示后加载并定位，避免阅读中突然跳动。发帖或回复成功后立即显示结果；失败时保留草稿并给出明确原因。用户可编辑或删除自己的主题与回复；删除采用软删除，保留楼层位置与后续回复的上下文。昵称修改后，历史帖子显示当前昵称。

浏览器首次打开门户时领取账户，不弹注册页面；导航显示随机昵称，点击进入简洁的「我的账户」面板修改昵称。默认昵称从预设词库加随机数字生成，碰撞时重试，长度 2–20 个字符；修改时去除首尾空格，限制长度和不可见控制字符。前端隐藏非作者的编辑按钮只是体验处理，最终权限判断在服务端。

## 身份、部署和既有数据

`POST /api/guest-sessions` 生成不可预测的随机会话密钥（至少 256 位），数据库仅保存密钥摘要、账户 ID、创建和失效时间；响应设置 `HttpOnly; Secure; SameSite=Lax; Path=/api` Cookie。生产环境使用 HTTPS，并让门户与 `/api` 处于同一站点；本机 HTTP 开发仅在 localhost/127.0.0.1 关闭 `Secure`，由 Vite 的 `/api` 代理连接后端。前端 API 默认改用相对路径 `/api`。应用启动时先请求 `GET /api/me`，没有会话时领取新账户；公开 GET 本身仍允许无会话访问。`PATCH /api/me` 修改昵称。会话有效期 365 天，活跃时续期；失效后创建新账户。前端先经 `GET /api/csrf` 获取 CSRF 令牌，再在所有变更请求携带 `X-CSRF-TOKEN`；服务端同时校验 Origin。账户不会基于浏览器指纹生成，也不接受请求体、`X-User-Id` 或前端本地存储的 ID 作为权限凭据。

新建项目的 `owner_account_id` 由服务端从会话填写；更新和删除均检查数据库中的该字段。前端提交的旧 `ownerId`/`ownerName` 不再决定归属，显示昵称来自账户表。已有项目保留公开展示，旧 `owner_id`/`owner_name` 字段保留以便迁移；由于旧 ID 可伪造，不能自动认领或据此授权编辑。需要恢复某个旧项目的编辑权时，由管理员核对后执行一次性归属映射。既有未提交的前端改动不混入此次改造。

现有「落地舱」使用浏览器生成的 `userId`，不作为社区账户的身份依据。本轮账户只覆盖项目与社区的作者操作；落地舱身份迁移单独设计，避免把不可信的旧 ID 直接绑定新账户。页面对用户展示的“账户”指项目与社区账户，落地舱暂沿用现有个人数据入口。

## 数据和接口

新增 `community_account`（ID、昵称、状态、时间）、`community_session`（账户 ID、密钥摘要、失效与撤销时间）、`community_board`（编码、名称、描述、排序、状态）、`community_topic`（板块 ID、作者账户 ID、可空项目 ID、标题、正文、回复数、最后回复时间、状态、时间）、`community_reply`（主题 ID、作者账户 ID、可空引用回复 ID、正文、楼层号、状态、时间）、`community_report`（举报者、目标类型与 ID、原因、状态、时间）；项目表新增可空的 `owner_account_id`。对主题列表的板块/最后回复时间、回复的主题/楼层号、项目关联和会话摘要建立索引。所有列表使用后端分页与总数，禁止一次拉取整个论坛。

公开读取：`GET /api/community/boards`、`GET /api/community/topics?board=&projectId=&keyword=&sort=&page=&size=`、`GET /api/community/topics/{id}`、`GET /api/community/topics/{id}/replies?page=&size=`；项目页用 `projectId` 查询关联主题。写入：`POST /api/community/topics`、`PATCH /api/community/topics/{id}`、`DELETE /api/community/topics/{id}`、`POST /api/community/topics/{id}/replies`、`PATCH /api/community/replies/{id}`、`DELETE /api/community/replies/{id}`、`POST /api/community/reports`。管理员使用 `POST /api/admin/session` 建立单独会话，经 `GET /api/admin/community/reports` 查看待处理举报，再由 `PATCH /api/admin/community/reports/{id}` 处理并可隐藏对应内容。响应统一沿用现有 `ApiResponse` 结构；错误区分 400 校验失败、401 会话缺失/过期、403 非作者、404 内容不存在、409 已删除/状态冲突、429 频率限制。板块编码固定，发帖可选已存在且可见的项目；关联项目不要求发帖者是项目所有者。

主题标题 5–120 字，主题正文 10–10000 字，回复正文 1–2000 字。正文首版为纯文本，换行可保留，URL 作为安全链接识别；前后端都不渲染用户提交的 HTML。列表返回摘要和计数，详情返回正文；作者昵称通过账户表查询，因此改名会更新历史展示。楼层号在事务中分配，不因软删除重排；新增和删除回复时在同一事务中维护回复数和最后活跃时间。

## 治理、异常与验证

公开匿名写入需对账户和 IP 做频率限制，初始阈值为每小时每账户 5 个主题、30 条回复，每日 5 次改名、10 次举报，每小时每 IP 最多领取 20 个账户；阈值从服务端配置调整。重复或超长内容给出可理解的错误。每条主题和回复提供举报入口，举报者须有有效会话。作者可软删除自己的内容，管理员可隐藏内容并处理举报。管理员通过服务端配置的独立密码建立管理会话，使用受保护的管理接口处理举报；普通随机账户不能自行提升为管理员。现有内容和 AI 管理接口若继续对公网开放，也必须在上线社区前加上同一服务端管理权限，不能沿用前端显示的“运维”角色当作授权。

接口失败时保留页面已加载内容与输入草稿，显示重试；若账户 Cookie 过期，前端提示“当前浏览器的账户已失效，将创建新账户”，避免静默把原草稿发成另一位作者的内容。板块或主题被隐藏后对普通用户返回 404。数据库迁移先增加新表和项目归属字段，再部署 API 与前端；在两端切换期间将旧项目写接口暂时关闭或一起发布，防止旧客户端绕过新归属检查。

验证包括：首次领取与刷新复用账户；不同浏览器隔离；昵称修改后旧帖显示新昵称；项目关联和跨板块检索；分页与并发回复楼层不重复；作者和非作者的编辑/删除；伪造旧 `X-User-Id` 无效；Cookie 丢失、过期、跨站请求、限流、举报和软删除；桌面与手机端的读帖、发帖、引用及新回复提示。后端通过单元和集成测试覆盖身份/归属/事务，前端通过构建、静态检查与浏览器关键路径验证。
